// case study — toughest production issue

P1: SAP gross-weight submission failing with HTTP 400

SEV: P1 April 2026 JSW Steel · AX4 platform 3 teams coordinated RESOLVED: same day
DETECT

Gross-weight submissions to SAP started failing

AX4's gross-weight submission to SAP returned HTTP 400 every time the KEMAR system re-triggered. Dispatch flow blocked — trucks could not be processed.

TRACE

Root cause found in the logs — and it wasn't on our side

Traced the request/response cycle through application logs. The failure came from incorrect material weight sent by SAP during delivery-order allocation — the gross + material equation didn't hold because SAP's material data was wrong.

COORDINATE

Drove the fix across three teams

Got the SAP team to correct the material data, the KEMAR team to revert the gross weight so the delivery order could be re-assigned, then re-triggered the gross-weight submission from AX4.

RESOLVE

Dispatch flow restored the same day

End-to-end resolution within the same business day. Documented the failure mode for future L1 triage.

Why this matters for DevOps: this incident is the reason I built OrderFlow — a project that re-designs this exact integration with a transactional outbox, async acknowledgment, idempotent retries, and a reconciler service, so this class of failure self-heals inste of paging a human.
